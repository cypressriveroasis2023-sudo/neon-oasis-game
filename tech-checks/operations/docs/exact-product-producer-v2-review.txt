bounds contention; the runtime also aborts bounded IO. This is deliberately more
conservative than row locks. Assess production contention before activation.
Queries use an indexed product/authority/observation-time prefix.

WHY THERE IS NO CLAIM OF A DISTRIBUTED ATOMIC HEALTH UPDATE
Source code proves three authority boundaries: native platform service client,
legacy camera database, and current Google Sheets. The existing epoch reader also
requires the verified user's auth.uid; its backing event table is explicitly
revoked from service_role. A legacy invoker transaction cannot read native private
source data, lock Google Sheets, or bypass that epoch boundary. The existing
publish_camera_connection_v1 compares saved local endpoint configuration, not
the cross-project source/identity authority. Reusing it as though it had those
checks would be unsafe. No permissions or auth claims are invented to bridge it.

Instead V2 implements this safe receipt protocol:
- Fully verify the source and reviewed identity, then probe only saved targets.
- Fully reread source/identity/configuration after all sockets finish.
- Stage an immutable, source-bound pending receipt with atomic local group CAS.
- Fully reread remote authority again AFTER staging; accept only the same guard
  and the same receipt payload with another atomic local physical/config CAS.
- When consuming any accepted receipt, read current complete source, read the
  matching receipt with local CAS, then reread complete source again. Require the
  same exact authority guard and a fresh completed observation. Otherwise Unknown.

A remote change in the gap between the last producer read and acceptance can
persist a historical scoped receipt. It cannot change global camera-health rows
and cannot be consumed against changed current authority. A regression injects
exactly that race: acceptance succeeds, fresh consumption returns Unknown, and
all global device/health/history rows remain byte-equivalent. This is explicit
snapshot-bound validation, not a distributed transaction or a zero-time race claim.
No update is made to camera_health_current/history, source, inventory or placement.
The unchanged existing publisher and schedule continue normally.
