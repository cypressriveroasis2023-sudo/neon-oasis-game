# Reviewed archive representation projection

This is a presentation-only correction for exact, independently reviewed archive-to-active representation pairs. It creates no physical asset, camera identity, provider association, Owner testimony, retirement, or source edit. Native equipment, tracker, component, history, address and coordinate records remain intact.

## Review and install contract

1. Review the generic SQL and runtime patch independently. Apply the SQL only in the native project after the source registry and Owner identity schema exist. No private data belongs in the repository.
2. The private review packet must contain the exact four reviewed before-images, existing canonical source rows, immutable archive/active row digests and source references, and a digest of the approved review. Confirm the full source roster has one retained active representation. A source row label or component similarity alone is insufficient.
3. Freshly re-read all four exact IDs and canonical sources. Check the archived record has no native GPS, location history, active assignment, installation, provider link, source binding, Owner claim or non-insert equipment audit. Read current legacy Owner/IT audits, devices and health identity evidence as well. Never refresh a changed before-image automatically.
4. Only an actual `postgres` administrative caller can invoke `app_private.cos_archive_import_reviewed`. Its provenance is `postgres_admin_reviewed_source_archive`. It does not impersonate an Owner or add an Owner audit. The private seed is supplied as a rollback-only review transaction; production application is a separate reviewed action.
5. Canonical operational updates keep the reviewed representation. Archived-target changes or canonical identity/association changes permanently revoke existing evidence; changing a value back does not restore it. The private evidence and revocation tables are immutable. A conflict is never automatically repaired or re-admitted; the existing reservation and history remain for a separately reviewed administrative recovery. A deliberate administrative cancellation is an insert into the private revocation table with reason `admin_revoked`.

## Reader and runtime contract

`public.cos_archived_representation_projection(p_organization_id)` returns `COS_ARCHIVED_REPRESENTATION_V1` evidence with explicit `active` or `conflict` state. It is bounded by the review import and uses the existing fixed organization. Its explicit service-role guard, empty search path and ACL deny anonymous/authenticated callers. `app_private` schema USAGE remains denied to service_role; existing source read functions and ACLs are unchanged. Before-image serializers fix the timezone to UTC so local SQL timezone does not change a reviewed timestamp's meaning.

`checkedArchivedRepresentations` validates the proof, the entire unfiltered native roster, exact row labels, both endpoints and cross-project Owner/IT/identity conflicts. Cycles, chains, shared endpoints, wrong families and stale pre/post reads fail closed. Family/base comparison rejects mismatches only; it never discovers a target or assigns a camera.

The source overlay can disregard an exact archived competitor only for its declared canonical native ID, after that complete validation. All other competitors and all existing camera/health proofs remain unchanged. Both source and archive proofs are re-read after lookups. `projectArchivedRepresentations` runs only after Owner placement, address/point and health verification have consumed the full roster; it filters display rows and recomputes display counts. `projectArchivedEquipmentRegistry` applies the same proof to the active equipment display. History and detail endpoints are untouched. Known stale or contradicted evidence shows both records in a visible review state and holds their map pins; it cannot silently recreate duplicate pins. The equipment registry shows an association-review message while preserving editable native fields. A completely unavailable first proof read retains ordinary visibility because no mapping has been established for that request.

## Initial admission and ongoing identity guards

Initial admission still compares all four before-images and canonical source rows exactly, including mutable timestamps, address and GPS. No changed before-image is silently accepted.

Ongoing projection binds the archived native/tracker before-images strictly and rejects new archived GPS, history, active assignments, provider/source bindings, non-insert equipment audits or Owner claims. The canonical guard instead binds its native ID, organization, full label, model ID/name/category, tracker ID/full label/key/family, and source association identity (native/tracker IDs, product ID, family and variant). Deletion, retirement, relabeling/reassignment, changed provider physical identity or changed source identity becomes a permanent conflict.

Canonical address, placement, GPS, operational status, source content/revision, source import time, generic updated_at and health observations do not invalidate a stable representation. Current verified canonical Owner/provider associations may carry legitimate Owner/IT audits; an unassociated generic audit or archived-label audit still creates a review conflict. Health verification always consumes the original complete roster. Neither the archive evidence nor its source-only competitor exception becomes a camera identity or a placement alias. The current health verifier deliberately rejects overlapping native and independently reviewed Owner-control identities; those warnings remain conflicts. A normal current Owner move carried by the unchanged native association retains one representation without creating a new health identity.

## Validation

The synthetic PostgreSQL/PGlite suite exercises real role switching with private schema access denied, exact before-image guards, immutable evidence, conflicting authority, permanent cancellation, source changes and timezone stability. Projection tests exercise the composed endpoints, full inventory checks, pre/post read changes, canonical point preservation, source-only overlay behavior and unchanged health inputs. A private replay tests the reviewed records without production access. That replay cannot substitute for fresh live preflight, especially active-assignment and cross-project evidence.
