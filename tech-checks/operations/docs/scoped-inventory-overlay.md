# Scoped inventory review

`db/scoped_inventory_overlay.sql` is a deployment candidate, not an applied
migration. It depends on the existing upload overlay and Owner identity actor
gate. This PR does not install SQL, activate a source, or deploy application code.

The administrator-only review function also checks the existing Owner actor and
tenant authorization. Its inputs are the expected active upload hash, monotonic
scoped revision, unique request ID, derived-map provenance, and exact before/after
operations. Customer assignment corrections retain the existing binding. A
`replace_source_hold` operation replaces a current source ProductId without
asserting physical identity: it retains the previous batch and its history, sets
the new binding to null, and keeps candidate associations in review. An explicit
`inventoryOnlyReason: "no_sim"` requires SHOP and renders “No SIM / no current IP.”
It never imports an old endpoint. This restriction cannot be relaxed by the
assignment operation.

Only the bounded Sniper/CAM V categories are admitted. Labels, category, lifecycle,
native IDs, endpoints, observations, activation and installation records cannot
be edited by these operations. When a customer changes, the old source-only
postal address is cleared from the new scoped row; it is retained in prior
evidence. No customer address becomes an installation location.

The base upload hash, payload hash, global timestamp, other records and tracker
authority timestamps stay unchanged. Each corrected row carries its own derived
evidence hash and source receipt time. Existing newer-source, Owner, location,
binding and collision guards continue to decide effective placement. The raw
source-inventory table is separate from physical identity and health totals.

`prepare-scoped-inventory.mjs` builds an offline review plan. Explicit source-only
replacement pairs are required to generate those operations. `scopedStatements`
produces private dry-run, apply and rollback SQL; it has no database/network path.
Keep actual source files, mappings, before snapshots, actor IDs, authorization
evidence and generated SQL outside git. A derived-map hash is never represented
as the original CSV byte hash.

Before application, deploy and verify the compatible reader, install the reviewed
schema candidate, and refresh the base/scoped revisions, exact before records and
binding guards. Run the dry-run in a transaction that rolls back; compare every
changed row and unchanged operational state. Application is a separate reviewed
step. Rollback requires the exact current base, scoped revision and active request
ID, advances the revision, and retains every batch and audit entry. Rolling back
or replaying a stale request cannot overwrite a later scoped change.

Local database tests use synthetic PGlite fixtures, including SQL generated by the
offline preparer. Projection and presentation tests cover newer Owner evidence,
source-only replacement, no-IP Shop inventory, lifecycle retention and unchanged
health/endpoint data. Browser coverage is in `sniper-inventory.browser.spec.mjs`.
