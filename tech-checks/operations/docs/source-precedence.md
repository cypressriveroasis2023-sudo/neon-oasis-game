# Reviewed source precedence

This adds a narrow reviewed exception for one native mHelpDesk installation source and one older, unmarked `MOVE_TO_ROOT` audit. It is not a newer-export-wins policy, an Owner move, a camera identity, or GPS verification. No data is admitted by installing these SQL files.

A SQL administrator reviews the exact current V1 FIELD source binding, current full legacy audit row hash, projected audit evidence hash, exact device roster and authorization evidence. The native review records the supplied reviewer/importer identity and authorization digest privately. It retains the expected prior source revision and emits a new immutable source revision and event through the existing source trigger. The source address/file/row/native guards remain unchanged. The old revision cannot be given different binding bytes.

The legacy administrator separately registers the returned exact binding. Registration takes the existing NOWAIT legacy locks and checks the full original audit row and device roster. It does not modify, delete or fabricate an audit, create an Owner session, change a device, enroll postal retries, reset a queue, write coordinates, or spend provider credits.

The effective map address requires both current native registry proof and fresh legacy registration verification, before and after lookup reads. The legacy RPC uses the existing verified Owner/IT reader gate, with service-role server reads; it does not grant Service users new rights. It returns only already-supplied safe bindings, never audit before-state, reasons or raw content. Optional read failure holds this override and leaves the rest of the map available. Reads are skipped when no decision exists, and are batched at 250 with request-scoped indexes.

The exception is valid only while there is exactly one related audit, its full row and projected digest match, it remains an unmarked Root action without placement/control/request/site/address fields, its timestamp precedes review, and the exact current device group matches. Any additional related Owner, IT, ordinary or cross-device audit holds it. Missing or relabelled devices/audits, a conflicting native variant or identity warning also holds it. Native GPS, Owner-verified coordinates and authoritative installed sites keep priority. Existing reviewed property estimates retain their current priority. Same-address Census/Geocodio caches can be reused through the existing job pipeline; a new source revision does not reset caches, attempts, budgets or the frozen postal cohort.

No-decision V1 and V2 serialization remains unchanged. The optional `sourcePrecedence` object is allowed only on V1 equipment-unit FIELD bindings. The same validator is used by the native read bridge, geocoder client and map binding parser. Every queue, claim, reserve, finish and read path rechecks the guarded legacy decision through the existing common binding lock or a replaced guard call. Existing function ACLs, security-definer status and search paths are preserved. Native scoped readers run as their existing owner, so the new native table and helpers grant no direct service-role access; legacy invoker queue helpers retain only the needed service grants.

## Deployment and reviewed data sequence

1. This patch is composed after the tracker V2 SQL/TypeScript contracts. Install `source-precedence-contract.sql` in both projects.
2. Install `geocodio-source-precedence.sql` in the legacy project and `cos-source-precedence.sql` in the native project. These create empty private review tables and backend contracts only.
3. Prepare complete upload bundles by running `node scripts/packageSourcePrecedenceFunctions.mjs <local-output-directory>` from `tech-checks/operations`. Each bundle has `function-name/<original files>` plus `_shared/sourcePrecedence.ts` and `_shared/package.json`, with entrypoint `function-name/serve.ts`. The script verifies every relative import via the TypeScript parser, hashes each unchanged source file, rejects traversal filenames, and emits manifests and upload payloads. Do not deploy root-level files with `../` upload names or rewrite imports. Preserve the existing function deployment settings, authorization behavior, environment and secrets. The operations bundle includes its existing source-recorded/archive dependencies.
4. Re-read the exact native source binding and both audit digests, plus the current audit/device roster. Keep UTC when capturing the PostgreSQL full-row digest. Verify actual user authorization and store its artifact SHA256, and identify the real administrator/importer; do not substitute an Owner identity.
5. Call private native `cos_source_precedence_admin_review(expected_binding, review_without_sourceRevision, reviewed_by, authorization_sha256)` using the existing SQL administrator. Save its full returned binding, old/new revisions and event IDs in the apply receipt. The review includes `reviewedSourceRevision`, so a stale source aborts. A current active decision cannot be silently replaced.
6. Register that returned binding through private legacy `cos_imported_precedence_admin_review(binding, reviewed_by, authorization_sha256)`. If audit or roster evidence changed, this aborts; the map and queue remain held without valid registration. The two projects are not a distributed transaction.
7. Let the existing bounded source scan observe the new event. Verify the map and queue with the current binding. Preserve provider budgets, caches, leases and postal enrollment. A source edit/GPS change generates another source revision and makes the old decision inactive.

## Limits and verification

This contract intentionally supports only one unmarked Root audit and an exact unsuffixed model match. More complex history, V2 tracker decisions, suffix aliases and multiple audit supersessions need a separate review. Read-before/read-after guards are not a distributed transaction; a change committed after the final read can only be observed on the next read. Legacy writers are excluded during each guarded SQL operation by the existing NOWAIT locks.

Tests use disposable synthetic databases and mocked providers. They cover immutable source revision churn, full/private audit changes, timestamp microseconds, later/cross-device audits, missing registration, roster drift, native GPS/site precedence, forged contracts, administrator-only writes, verified reader roles with private-schema access denied, preserved SQL function properties and bodies, unchanged V1/V2 serialization, and the 401-row real handler with unavailable optional evidence. No real unit is moved. Real multi-session lock contention remains covered by the existing imported-geocode lock protocol; this patch does not introduce a different legacy lock order.
