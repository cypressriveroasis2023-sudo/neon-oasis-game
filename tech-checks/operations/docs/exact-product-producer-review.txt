exclusive current tracker IP. It does not supply a writable equipment identity.

Local model and collector guarantees
- Explicit 1–64 exact Product IDs; the planner never selects by family/name/IP.
- Uses buildExactProductConnections with null portStatus to preserve all its
  complete-census, source, tracker, lifecycle, identity and collision gates.
  Only its exact final missing-proof reason permits further review. This text
  dependency is deliberate fail-closed coupling; a future refactor should expose
  a shared machine-readable admission result. No fake successful proof is made.
- Additional exact committed identity, source/profile, lifecycle, enabled flag,
  unique device ID, public literal, revision and 1–32 unique saved-port checks.
- One target at a time, four concurrent ports maximum, 2.2s probe budget, 4s IO
  budget and 48s run deadline. Bounded wrapper aborts on timeout. Real adapter
  must cancel sockets and close late sockets; a JS timeout cannot enforce that
  on an adapter that ignores AbortSignal. No real socket adapter is included.
- Whole source/identity/endpoint snapshot reread after probes, before publishing.
  A guard binds mHelp, complete tracker records, identity reservations and every
  saved endpoint configuration. Only the reread tracker observation time and
  old health proofs are omitted. Current source verification still checks time.
- Complete probe outcomes are validated with completedSavedTcpCheck. A complete
  refusal/timeout is Offline; routing/DNS/auth/permission/partial/technical failures
  are Unknown and make no publication call. No counters increment on a hold.
- Run/product/guard-derived receipt key plus immutable payload digest. A failed
  publication response is not retried. Missing/malformed/lost receipts produce
  publication_uncertain, never a successful write claim or another failed check.

REQUIRED PUBLICATION CONTRACT / MINIMAL MIGRATION DESIGN (NOT APPLIED)
The existing publish_camera_connection_v1 performs config CAS, but does not

Before creating SQL, resolve the cross-project permission boundary explicitly.
The current Owner/IT reader is not a schedule principal. No authorized scheduled
reader or cross-source atomic commit token was established in this work.

Minimal reviewed schema design in the publication database:
1. A private authority epoch/attestation store, with authority epoch primary key,
   complete canonical guard, source SHA, tracker SHA, identity revision/epochs,
   verified-at and expires-at, and explicit superseded/revoked state. A protected
   verifier alone may register it after the existing safe readers validate the
   complete source. Registration is not an identity admission. External Sheets
   cannot participate in a Postgres transaction: define freshness as the latest
   verified complete snapshot, disclose the post-read external-change window,
   and reject this design if stronger distributed atomicity is required.
2. A private immutable receipt store keyed by receipt_key, with payload SHA,
   Product ID, device ID, authority epoch/guard, configuration revision, original
   observation time and outcome. Same key/same payload returns the original
   receipt without another health/history write. Same key/different payload
   rejects. Do not extend the observation time on replay.
3. A narrowly scoped new publication wrapper. In one transaction, lock the active
   authority epoch and exact endpoint, check epoch/guard/expiry/revocation and the
   committed Product/native/resource identity and reservations, then compare
   enabled state, lifecycle, ownership/source/profile, IP, complete ports and
   revision. Recheck actual complete probe schema and newest-observation ordering.
   Only then delegate to the unchanged saved-endpoint publication primitive under
   a separately reviewed source policy and insert the immutable receipt. Both
   writes commit together or neither does. No non-target inventory/placement/
   identity/configuration/Sheet rows may be written. Reject a stale epoch or
   changed/ABA revision even if the public IP returns to its prior value.
4. No PUBLIC/anon/authenticated execute or table access, no new grants in this
   patch. Exact execution role and safe-reader permissions require separate
   review. Do not solve the boundary with an unrestricted SECURITY DEFINER.

These are schema/transaction acceptance criteria, not runnable migration SQL or
an assertion that a distributed atomic publisher already exists. Generate the
actual migration only after authority store ownership, principal, role and source
publication policy are reviewed. Test SQL locally against the real publisher:
concurrent source/config/revocation drift, rollback after inner RPC, receipt replay,
conflicting replay, latest-result CAS and denied-role tests are activation gates.
Mocked adapters here do not establish database atomicity or authorization.
