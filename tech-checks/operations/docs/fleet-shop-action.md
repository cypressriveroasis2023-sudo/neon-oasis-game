# Direct Fleet Shop action

Owner and verified IT can return a registered COS equipment unit to Shop / ROOT from its Fleet card. The action reads only its native equipment identity and placement, requires a reason, and commits through the service-only `cos_fleet_shop_action_v1` RPC. Camera association, health, GPS, mHelp connectivity and Field Map reads are not prerequisites. Service access is denied.

The database locks the selected native unit, checks its displayed identity and placement revision, updates only `status`, `current_location_type`, and `updated_at`, and adds an actor-attributed move receipt. Existing audit and lifecycle triggers retain before/after records. It preserves native UUIDs, models, serial/SIM/IP fields, installed-site references, GPS/history, provider associations and job records. Same-request replay is idempotent; conflicting request reuse or stale identity is denied. A failed client response blocks another submission until saved placement is checked.

When a currently verified accepted mHelp Product-ID binding exists, the move captures that source reference before the native placement update invalidates the source's broad guard. Fleet applies the confirmed physical placement to the corresponding Product ID without changing its accepted upload or digests, and without restoring a held camera association. A later explicit mHelp file supersedes older manual placement; routine API rereads retain the manual placement for the same durable Product ID and source label. Product-ID totals and address pins use the derived placement; the underlying accepted inventory remains available to the import workflow unchanged.

Three additive migrations create the private receipt ledger and service-only functions. They grant no direct execution to anonymous or authenticated browser roles and change no equipment by themselves. Runtime preparation adds the route and final Field Map projection to the actual deployed bundle, asserting every unrelated byte is preserved. Previous camera diagnostics, mHelp token renewal and other runtime overlays remain intact.

Validation uses synthetic native database records, Owner/IT/Service bridge transports, source/roster projections, and phone/desktop browser checks. Deployment does not create production test moves. This action records COS placement; it does not claim a completed mHelp or Google Sheets write.
