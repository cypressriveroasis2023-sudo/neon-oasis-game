Boundary and consistency
The native project owns runs, the authoritative admitted roster generation, and
health publications. commit_result locks the tenant lease, current authority and
actor profile/role rows, validates current Field eligibility, identity uniqueness,
restrictions, endpoint revision/IP/ports/profile and observation times, then writes
the health outcome, monotonic failure count, receipt and run row in ONE native
PostgreSQL transaction. save cannot invent successful outcomes or receipts.
Repeated exact commit requests return the same receipt without incrementing the
failure count. A lost response can be resolved by reading the run. Successful rows
survive later stale worker saves. A failed/partial refresh never renews timestamps.

This does NOT transact across the native and legacy Supabase projects. Native
health is authoritative for managed Avigilon endpoints. Legacy health is neither
written nor required for success. The shared summary reads native publications,
not a legacy replica. No distributed-transaction guarantee is made. There is no
legacy replication worker in this patch; replica_ack_at is reserved metadata,
never a success signal. Any future legacy copy must carry the native receipt,
be idempotent and reject older generations/receipts; it cannot drive these views.

Cross-project source protocol (required before enablement)
Every writer of placement, restrictions/DNU, activation/monitoring, resource
identity, IP, port list, profile or connection revision must participate. This
includes scheduled provider/import jobs and administrative SQL, not just UI edits.
1. Acquire native fence(actor, tenant). This closes publication/health reads,
   invalidates the current lease, and returns an exclusive generation token.
2. Only after confirmed fence acquisition may that writer mutate remote/native
   source records. withAvigilonAuthorityFence implements this ordering.
3. Read back complete reconciled inventory, reviewed identity and endpoint state;
   derive the roster with auditedAvigilonRoster. Recheck source revisions around
   the read, with no competing source writers allowed.
4. admit(actor, tenant, exact_generation, roster) reopens publication. The next
   run binds its generation in a database trigger, never a client timestamp.

Fence acquisition fails when already closed; there is no expiry/takeover. A crash,
ambiguous write response or failed readback leaves authority closed. Recovery must
quiesce the original writer, verify all source state, and explicitly admit the
held generation through the reviewed administrative path. Merely copying source
state asynchronously, or post-probe re-reading it, does NOT satisfy this protocol.
Candidate native integration: avigilon_native_source_fences.sql installs BEFORE
STATEMENT hooks on 25 authority tables (the exact list is in that file). Native
inventory upload/scoped apply and rollback, equipment CRUD, tracker placement,
MHelp/Sheets placement jobs and owner/provider identity writes invalidate native
authority in their own source transaction. Transaction rollback restores the
previous generation. Every committed statement increments generation even while
closed, so a concurrent source write defeats stale admission. Missing tables
abort installation. These hooks are NOT installed. Scheduled source jobs will
conservatively close health until reviewed readback/admission; this availability
cost is intentional. The cross-project helper's pre-write token cannot be reused
for native mutations covered by these hooks: native orchestration must capture
the resulting committed generation before beginning complete readback, then
recheck that generation during admission. Never obtain a fresh token after
unbracketed readback.
The candidate coordinator below implements this admission orchestration; the
trigger itself only closes authority and never performs remote readback.
Shared PR178 functions are unchanged. After merging PR178,
verify its final tables remain covered; its label-only/authority-time semantics
are inputs to roster readback, never authority-token bypasses.

Readers
Native read_health returns one authority generation, admitted roster revision,
roster membership and receipts from one statement snapshot. The handler reads
this envelope BEFORE identity/placement/endpoint reads and rechecks the token
AFTER them. A closed or changed generation/roster fails the whole read. Receipt
membership must match exactly one admitted roster unit and one current native
identity claim for the device. Fleet requires the same token on health and field
map and verifies receipt membership against current Field inventory. A change
between the two HTTP reads therefore fails closed. Generation increments prevent
ABA even when a roster revision is reused. This requires all source writers to
participate; it does not make cross-project reads serializable by themselves.

Consumers
Operations summary-v3 uses projectAvigilonHealth whenever the optional run runtime
is provided; an unavailable/malformed native read fails the refresh. The existing
shared fleet pair feeds Fleet, Camera Health, details and CSV. Pending/new runs,
closed fences, changed endpoints, Shop, inactive and restricted units suppress
old service health. Managed identity tombstones prevent removed mappings from
reviving old legacy observations. Provider health, placement, activation, IPs,
router, power and video remain separate. CSV adds basis, observation time, explicit
unknown channel/video coverage and receipt IDs. Run reports name receipts too.
Failure retains inventory/location; current health becomes unknown. Historical
report rows remain historical evidence and never move inventory.

Source-operation continuation (candidate, NOT installed or enabled)
The remaining protocol is implemented by avigilon_source_operations.sql in the
native project and avigilon_legacy_source_guard.sql in the legacy project.
A native source operation stores immutable commands and holds authority closed.
Legacy apply locks its gate, executes the allowlisted source commands and records
an immutable sealed receipt in ONE legacy transaction. There is no open remote
permit, time lease, or permit expiration. A retry returns the exact saved receipt;
it cannot reopen the operation or mutate after native admission. A new legacy
operation requires a newer native generation from a new, committed native hold.
These are two independent database transactions, NOT a distributed transaction.
The trusted service coordinator is responsible for carrying the committed native
ticket and reading the committed legacy seal; neither browser can issue tickets.

Ambiguous/lost responses retain a durable pending operation. Reconciliation
resumes its exact stored commands, reuses the sealed result and brackets trusted
readback with both the native generation and legacy operation seal. Native finish
rechecks generation and actor/tenant inside its transaction before admission.
The original unverified admit entrypoint is disabled by the candidate SQL.
Explicit cancellation serializes on the same legacy gate: if a writer committed,
it returns the actual outcome; otherwise it records a permanent cancellation
receipt so a delayed writer cannot execute. It then performs verified readback
before reopening health. Cancellation is not rollback and is not automatic.
Revoked initiating actors remain closed pending separately authorized recovery.

Routine native source hooks leave a durable dirty authority. The configured
checks.readHealth and managed checker run reconciliation before reading/checking.
The server-only readAuthorityRoster method reuses the actual field-map and identity
projection with fixed trusted source headers. There is no browser bypass header.
This handles inventory apply/rollback, tracker/native placement and native identity
updates without modifying PR178 functions. The production candidate resumes the
stored initiating actor (rechecking current authorization), not the page visitor.

Legacy guards cover camera_devices, equipment_master and camera_inventory_audit.
Raw event ingress stays in legacy storage; only its ordered projection runs in a
fenced operation, so raw provider event bodies are not copied into native tickets. Guarded server clients integrate provider reconcile,
Vigilant sync, Recon connect and Recon webhook, including ordered event projection.
Direct unguarded source writes are rejected, including administrative SQL unless
it explicitly uses the reviewed operation path. Routine integration heartbeats,
provider health, credential references and credential configuration are not
Avigilon roster inputs and are deliberately outside this gate; authoritative
camera identity, endpoint and activation changes still go through camera_devices.
The native audited Avigilon roster does not derive identity from integration
heartbeat metadata. Credential access/storage is unchanged.

Manual connection, placement, add/remove RPCs use the authenticated native bridge
and the original legacy RPC with the verified legacy actor, retaining original
role checks and revision guards. Arbitrary RPC names and actor overrides are not
accepted. Scheduled direct checks and provider direct mode dispatch to native
receipt-backed runs in the reviewed runtime. Browser manual managed checks do the
same; successful outcomes without receipts are rejected. Legacy current-health
reads for managed rows use native receipt data; no old port detail is fabricated.
A missing publication clears current service health while retaining device/source
records. Database guards reject legacy health writes for sniper/camv resources.
