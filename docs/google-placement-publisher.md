# Guarded 2027 tracker publishing

`cos-sheets-placement-publish` publishes only confirmed, recently observed assignments from the separately reviewed mHelpDesk equipment-ID crosswalk. It uses the existing scheduler verifier, server-held Google service-account JSON and the fixed 2027 workbook. Editor access on that workbook must be verified before enabling its default-off private control. It performs no sharing changes, delegated-user authorization, ticket actions, mHelpDesk writes, operational imports or GPS/provider changes.

The publisher has administrator-admitted bindings for an exact equipment ID, Google sheet ID, row number and complete displayed unit label. Its baseline contains only the identity, placement, customer and site/project cell values plus validation/chip flags. These private bindings and actual customer data never belong in GitHub. Newly added equipment and shifted/renamed rows require a new reviewed binding. The existing 29 nonstandard placement cells and unresolved decimal/hardware/lifecycle identities are not automatically admitted.

Normal equipment tabs permit B (placement), D (customer) and E (site/project). Solar Poles & Skids permits F (status), E (customer) and C (site/project); its B installation date is excluded. Every write is a single-cell `updateCells` with `fields:userEnteredValue`. Physical addresses, passwords, IPs, provider status, installation dates, Last Verified, styles, validation and layout are outside the write boundary. Existing equivalent Shop names/spellings are preserved. Formulas, chips and changed/unsupported validation are held.

Each run rechecks the native/manual/GPS authority guard, source freshness and exact current Sheet cells. Native edits or manual Sheet changes hold publishing. A second live Sheet read must produce the identical plan; the database then rechecks the source and records the exact intent before Google POST. At most 60 rows/180 cells are sent in one atomic batch. The Google readback must match each intended cell and metadata before its saved baseline advances. Timeouts retain the pending intent: exact matching readback can recover it, while a different pending assignment stays held. Unlinked and held units are left alone.

Google Sheets does not offer compare-and-set cell updates. A collaborator editing during the interval between the last read and POST can race this publisher. Readback detects divergent final values but cannot prove that an intervening edit was never overwritten. Do not claim absolute concurrent-edit protection; investigate a conflicting row rather than automatically replacing its baseline.

The original connection panel continues to perform its read-only readiness check. Publisher status is separately available through the protected scheduler endpoint and service-only RPC. Receipts expose aggregate counts only. The 15-minute publisher schedule should run after the source observation job; both private controls and each cron job can be disabled without deleting history. Preserve pending intents when stopping it.

Read all identity labels for duplicate detection, but limit placement/customer/site ranges to the last admitted row on each tab. Empty dropdown rows otherwise produce oversized responses. Google requests use compact JSON, and protected failure diagnostics contain only static phases, service names/status codes or enumerated layout errors.
